# MCP OAuth and Passphrase Consent Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task-by-task.

**Goal:** Let claude.ai and Claude on the phone connect to `/mcp` with OAuth, approving each connection with an owner passphrase, while Claude Code keeps working with a Claudia API token.

**Architecture:** The Worker's default export becomes `OAuthProvider` from `@cloudflare/workers-oauth-provider`. The provider owns `/mcp` (API route), `/token`, `/register` and the `/.well-known/*` discovery documents. Everything else, including `/api/*` and the consent page at `/authorize`, goes to the existing Hono app as the provider's `defaultHandler`. A Claudia API token (`cl_…`) on `/mcp` is accepted through the provider's `resolveExternalToken` hook. OAuth grants call the app in-process through a key-gated internal identity, because an OAuth access token is not a Claudia token.

**Tech Stack:** `@cloudflare/workers-oauth-provider@1.2.3`, Cloudflare KV (`OAUTH_KV`), Hono, Vitest in workerd.

Design: `docs/plans/2026-10-25-remote-mcp-design.md` (step 2 of "Order of work"). Step 1 (tools and handler) is done and deployed.

## Verified facts (spiked 2026-10-25 in workerd with `@cloudflare/vitest-plugin`)

- Version 1.x is a rewrite of 0.x. Older blog snippets are stale (`allowImplicitFlow` now throws). Read `node_modules/@cloudflare/workers-oauth-provider/README.md` and its `docs/` (especially `consent-page.md`, `resource-servers.md`, `migration-1.x.md`) before writing code.
- No peer or runtime dependencies. It imports `cloudflare:workers`, so it only runs in workerd. Works with Hono, which only needs `fetch(req, env, ctx)`.
- Needs KV binding `OAUTH_KV`. In tests the vitest plugin provides local KV when `"kv_namespaces":[{"binding":"OAUTH_KV"}]` is in the wrangler config.
- Constructor (all confirmed): `apiRoute: "/mcp"` (prefix match), `apiHandler`, `defaultHandler`, `authorizeEndpoint: "/authorize"` (required; never served by the library), `tokenEndpoint: "/token"`, `clientRegistrationEndpoint: "/register"`, `scopesSupported`, and **`resourceMetadata: { resource, authorization_servers }` (required)**. Optional: `resolveExternalToken`, `clientRegistrationCallback`, `clientIdMetadataDocumentEnabled`, `accessTokenTTL` (default 3600 s), `refreshTokenTTL` (default 30 days), `refreshTokenIdleTTL`.
- A 401 on the API route carries `WWW-Authenticate: Bearer realm="OAuth", resource_metadata="https://claudia.alphajuliet.com/.well-known/oauth-protected-resource/mcp"`, plus CORS headers. That settles the design doc's open item on the challenge header.
- Discovery documents are served by the provider: `/.well-known/oauth-protected-resource/mcp` and `/.well-known/oauth-authorization-server` (PKCE S256 only).
- `resolveExternalToken({ token, request, env })` is consulted only for tokens that are not in the provider's own `user:grant:secret` format, so `cl_…` tokens reach it. It returns `{ props, audience } | null`; `audience` must equal `resourceMetadata.resource`. The result arrives in the API handler as `ctx.props` and `ctx.auth = { token, audience, scope, … }`.
- For OAuth tokens `ctx.props` is exactly what was passed to `completeAuthorization({ props })`.
- Helpers on `env.OAUTH_PROVIDER`: `parseAuthRequest`, `lookupClient`, `describeConsent` (gives `clientName`, `clientDomain`, `redirectHost`, `redirectIsLoopback`, `scope`), `beginConsent` (returns `{ handle, headers }`: a one-time handle valid for 10 minutes plus a `__Host-oauth-consent-…` cookie, the library's CSRF protection), `approveConsent(req, handle, { scope })`, `denyConsent(req, handle)`, `completeAuthorization({ request, userId, metadata, scope, props })`. `userId` must be non-empty and contain no ":".
- Refresh tokens rotate (the previous one stays valid until its replacement is first used).
- There is **no built-in redirect URI allowlist**: any `https` URI or loopback `http` URI is accepted at registration. We enforce our own in `clientRegistrationCallback`, and show `redirectHost` on the consent page (a spec MUST).
- `global_fetch_strictly_public` is only needed for `clientIdMetadataDocumentEnabled: true` (the library fetches the client's metadata URL; the flag stops those fetches being routed to same-zone origins). We could not confirm whether claude.ai uses client metadata documents or dynamic registration, so we enable both. That requires compatibility date 2024-11-11 or later (the repo has 2026-10-01).

## Decisions already made

- Consent is gated by an owner passphrase (`OWNER_PASSPHRASE`, a Worker secret already set in production; KV namespace `OAUTH_KV` already created with id `c552af60bd2a4323b8bab3bf60628033`). No Cloudflare Access.
- OAuth grants are read/write only, never admin, and there are still no delete tools. Scope `tasks:write` gives the `write` scope, `tasks:read` gives `read`.
- Throttle: after 5 wrong passphrases in 15 minutes, further attempts are refused until the counter expires. One global counter in `OAUTH_KV` (single owner, so a per-address counter would only help a distributed guesser).
- Allowed redirect URIs: `https://claude.ai/api/mcp/auth_callback`, `https://claude.com/api/mcp/auth_callback`, and loopback (`http://localhost:*`, `http://127.0.0.1:*`) for Claude Code.
- Claude Code keeps using a Claudia API token. No change to what it does.

```ts
// worker/src/oauth/passphrase.ts
export const MAX_FAILURES = 5;
const WINDOW_SECONDS = 15 * 60;
const KEY = "passphrase:failures";

export type PassphraseResult = "ok" | "wrong" | "locked";

const digest = async (s: string) => new Uint8Array(await crypto.subtle.digest("SHA-256", new TextEncoder().encode(s)));

/** Constant-time comparison of two strings of any length (compares their SHA-256 digests). */
async function same(a: string, b: string): Promise<boolean> {
  return crypto.subtle.timingSafeEqual(await digest(a), await digest(b));
}

/**
 * Check the owner passphrase, with a global throttle: after MAX_FAILURES wrong
 * attempts inside the window, everything is refused until the counter expires.
 * Refused attempts do not extend the lockout. The count is best effort (KV is
 * not atomic), which is enough to make guessing impractical for one owner.
 */
export async function checkPassphrase(kv: KVNamespace, supplied: string, expected: string | undefined): Promise<PassphraseResult> {
  const failures = Number((await kv.get(KEY)) ?? 0);
  if (failures >= MAX_FAILURES) return "locked";

  if (expected && supplied && (await same(supplied, expected))) {
    await kv.delete(KEY);
    return "ok";
  }
  await kv.put(KEY, String(failures + 1), { expirationTtl: WINDOW_SECONDS });
  return "wrong";
}
```

```ts
// worker/src/lib/internal.ts
import type { Scope } from "./router";

/** Random per isolate and never sent anywhere: only in-process callers can present it. */
export const INTERNAL_KEY = Array.from(crypto.getRandomValues(new Uint8Array(32)), (b) => b.toString(16).padStart(2, "0")).join("");

/** Headers for an in-process call to the app on behalf of an OAuth grant. Admin is never granted. */
export const internalHeaders = (scopes: readonly Scope[]): Record<string, string> => ({
  "X-Claudia-Internal": INTERNAL_KEY,
  "X-Claudia-Scopes": scopes.filter((s) => s !== "admin").join(","),
  "X-Claudia-Client": "mcp",
});
```

```ts
const internal = c.req.header("X-Claudia-Internal");
if (internal && internal.length === INTERNAL_KEY.length && timingSafeEqual(internal, INTERNAL_KEY)) {
  const granted = (c.req.header("X-Claudia-Scopes") ?? "").split(",").filter((s): s is Scope => s === "read" || s === "write");
  const needed = requiredScope(c.req.method, c.req.path);
  if (!allows(granted, needed)) throw new ApiError(403, "forbidden", `This connection needs the '${needed}' scope`);

  c.set("scopes", granted);
  return next();
}
```

```ts
export function redirectAllowed(uri: string): boolean {
```

**Step 2: Compose in `index.ts`.**

```ts
import OAuthProvider from "@cloudflare/workers-oauth-provider";

const RESOURCE = "https://claudia.alphajuliet.com/mcp";
const SCOPES = ["tasks:read", "tasks:write"];

// consent routes live on the Hono app
app.route("/", consentRoutes);   // GET/POST /authorize (remove the old app.all("/mcp") line)

export const provider = new OAuthProvider<Cloudflare.Env>({
  apiRoute: "/mcp",
  apiHandler: {
    fetch: (req, env, ctx) => {
      const props = (ctx as { props?: { kind?: string; scopes?: Scope[] } }).props ?? {};
      const auth = (ctx as { auth?: { token: string } }).auth;
      const identity: McpIdentity =
        props.kind === "apitoken" && auth
          ? { kind: "apitoken", secret: auth.token, scopes: props.scopes ?? [] }
          : { kind: "oauth", scopes: props.scopes ?? ["read"] };
      return handleMcp(req, env, ctx, app, identity);
    },
  },
  defaultHandler: { fetch: (req, env, ctx) => app.fetch(req, env, ctx) },
  authorizeEndpoint: "/authorize",
  tokenEndpoint: "/token",
  clientRegistrationEndpoint: "/register",
  clientIdMetadataDocumentEnabled: true,
  scopesSupported: SCOPES,
  resourceMetadata: { resource: RESOURCE, authorization_servers: ["https://claudia.alphajuliet.com"] },
  clientRegistrationCallback: ({ clientMetadata }) =>
    (clientMetadata.redirect_uris ?? []).every(redirectAllowed) ? undefined : { error: "invalid_redirect_uri", error_description: "Redirect URI not allowed" },
  resolveExternalToken: async ({ token, env }) => {
    const row = await lookupToken(createDb(env.DB), token);
    return row ? { props: { kind: "apitoken", scopes: row.scopes }, audience: RESOURCE } : null;
  },
});

export default provider;
```

## Risks and how this plan handles them

- **The OAuth library is new (1.x) and its docs differ from older posts.** Implementers read the installed README and `docs/` first; the spike already proved the flow in workerd.
- **Breaking Claude Code.** Its API-token path goes through `resolveExternalToken`, and all existing `mcp.test.ts` cases must pass unchanged apart from the helper and challenge header.
- **A forged internal identity.** The key is random per isolate, compared in constant time, never granted admin, and tested with a guessed key.
- **Passphrase guessing.** Throttled at 5 per 15 minutes; locked-out attempts do not extend the lockout; the page has no cookies of ours and strict headers.
- **Open redirect or token theft through client registration.** Redirect URIs are limited to Claude's callbacks and loopback; the consent page shows the destination host.
- **Static assets swallowing the new paths.** `run_worker_first` lists them, and the discovery tests hit each path.
- **claude.ai behaving differently from the spec.** Tested only by Andrew in Task 7; both client registration and metadata documents are enabled to cover either.
