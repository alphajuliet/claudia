# Keyboard Commands Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Drive the desktop web app from the keyboard: a command registry, a highlight that moves through rows, panel following, search, a shortcuts overlay and a focus-trapped drawer.

**Architecture:** Pure key matching and wrap-around movement in `web/src/lib/keymap.ts`, the command list in `web/src/lib/commands.ts`, both unit tested. A `KeyboardProvider` (`web/src/ui/keyboard.tsx`) owns one window `keydown` listener and a handler registry; components register handlers with `useCommand(id, handler)`. The highlight follows DOM focus: rows are focusable, and focusing one (by key, click or focus return) makes it the highlight. Design: `docs/plans/2026-10-31-keyboard-design.md`.

**Tech Stack:** React 19, TanStack Query 5, wouter 3, Vitest 4 + jsdom + Testing Library (`userEvent.keyboard`).

### Task 1: Key matching and commands

**Files:** create `web/src/lib/keymap.ts`, `web/src/lib/commands.ts`, `web/src/lib/keymap.test.ts`.

`commands.ts`:

```ts
export type CommandId = "next" | "previous" | "open" | "close" | "complete" | "rename" | "capture" | "search" | "help"
  | "goInbox" | "goToday" | "goNext" | "goWip" | "goWaiting" | "goSomeday";
export interface Command { id: CommandId; label: string; keys: string[] }
/** Every command, in the order the shortcuts overlay lists them. Keys are `KeyboardEvent.key` values; "g i" is a chord. */
export const COMMANDS: Command[] = [
  { id: "next", label: "Next task", keys: ["j", "ArrowDown"] },
  { id: "previous", label: "Previous task", keys: ["k", "ArrowUp"] },
  { id: "open", label: "Open task details", keys: ["Enter", "o"] },
  { id: "close", label: "Close task details", keys: ["Escape"] },
  { id: "complete", label: "Complete task", keys: ["x"] },
  { id: "rename", label: "Rename task", keys: ["e"] },
  { id: "capture", label: "Add a task", keys: ["c"] },
  { id: "search", label: "Search", keys: ["/"] },
  { id: "goInbox", label: "Go to Inbox", keys: ["g i"] }, … goToday "g t", goNext "g n", goWip "g w", goWaiting "g o", goSomeday "g s",
  { id: "help", label: "Keyboard shortcuts", keys: ["?"] },
];
```

`keymap.ts`:

- `createMatcher(commands, chordMs = 1500)` returns `{ match(key: string, now: number): CommandId | "pending" | null }`. A key that starts a chord returns `"pending"`; the next key within `chordMs` completes it (`"g i"` → `goInbox`) or cancels it (returns null, and does not run its own binding). After the timeout the pending prefix is forgotten and the key is matched alone.
- `ignoresKeys(event: { ctrlKey; metaKey; altKey; target })`: true with Ctrl, ⌘ or Alt, or when the target is a text-like `input` (not checkbox, radio, button, submit, reset, range, color, file), `textarea`, `select` or contenteditable element.
- `wrapIndex(current: number, length: number, delta: 1 | -1): number`: `-1` current means none (`delta` 1 → 0, -1 → length − 1); otherwise wraps; length 0 → -1.

Tests: single keys, `ArrowDown`, chord within and after timeout, unknown second key cancels, an unbound key → null, modifiers and fields ignored (a checkbox is not ignored), wrapIndex at both ends and from none.

### Task 2: Keyboard provider, navigation, search and help

**Files:** create `web/src/ui/keyboard.tsx`, `web/src/ui/SearchScreen.tsx`, `web/src/ui/Shortcuts.tsx`, `web/src/ui/keyboard.test.tsx`; modify `AppShell.tsx`, `Sidebar.tsx`, `screens.tsx` (export `useGroupedSections`), `styles.css`.

- `KeyboardProvider` adds one window `keydown` listener. It skips `e.defaultPrevented`, `ignoresKeys(e)`, and `e.isComposing`. On a command it calls the most recently registered handler for it; a handler may return `false` for "not mine", and only a handled key (or a pending chord) gets `preventDefault()`.
- `useCommand(id, handler | undefined)`: registers while mounted, always calling the latest handler (keep it in a ref).
- In `AppShell`: `g` commands navigate to the views; `search` navigates to `/search`; `help` opens `Shortcuts`; `close` closes the panel when open (otherwise not handled).
- `SearchScreen` at `/search` (route before `/:view`): `<h1>Search</h1>`, a search field (label "Search", `type="search"`, autofocus) whose value starts from `?q=`; typing updates `?q=` with `replace` after 250 ms, keeping `?task=`. Results: `useTasks("status=open&limit=500&q=…")` grouped by `useGroupedSections`; empty `q` shows "Type to search titles and notes." and no request. Escape in the field blurs it.
- Sidebar: "Search" link above the views.
- `Shortcuts`: `role="dialog"`, `aria-modal`, `aria-label="Keyboard shortcuts"`, focused on open, a table of `COMMANDS` labels and keys (shown as `<kbd>`, chord as "g then i", arrows as ↓ ↑, Escape as Esc), a Close button; Escape (stopping propagation) or the backdrop closes it and focus returns to where it was.
- Test fake: filter on `q` (title or notes contains, ignoring case).

Tests: `g t` goes to Today; `g` then a pause past 1.5 s (fake `Date`? use the matcher's `now` from `Date.now()`) is covered by unit tests, so here only the happy path; typing `j` in quick add types it; `/` opens search with the field focused, typing finds a task by notes and puts `?q=` in the address; `?` opens and Escape closes the shortcuts; Escape closes the panel.

### Task 3: The highlight

**Files:** modify `TaskList.tsx`, `TaskRow.tsx`, `TaskDetail.tsx`, `selection.ts`, `AppShell.tsx`, `QuickAdd.tsx`, `styles.css`; create `web/src/ui/highlight.test.tsx`.

- Rows (`li`) get `tabIndex={-1}` and `data-task-id`; the heading button gets `data-task-id`. `onFocus` on either sets the list's highlight to that task (so clicks and focus return also move it). The highlighted row has class `highlighted` (outline).
- `TaskList` keeps `highlightId` (reset when the path changes) and the visible order (headings and rows, as rendered). It registers:
  - `next` / `previous`: from the highlight (or, with none, the open task if visible, else none), `wrapIndex`; focus the row; when the panel is open, `select(id, { follow: true })`.
  - `open`: only when focus is on a row element itself or on `body` (so Enter on buttons and links keeps working); selects the highlight.
  - `complete`: completes the highlighted task (not headings) through `useComplete`.
  - `rename`: clicks the highlighted row's title button (opens the inline editor).
- When the highlighted task leaves the list (completed, deleted, moved), the highlight moves to the row now at its old index (or the last row), and that row takes focus if focus was on the old row or on `body`.
- `useSelectedTask().select(id, { follow })`: `follow` navigates with `replace` and tells the panel not to take focus (a module-level flag read once by `TaskDetail`'s focus effect).
- Closing the panel (Escape or Close) focuses the closed task's row if it is on screen.
- `QuickAdd` registers `capture` (focus its field).

Tests: `j` highlights and focuses the first row, `k` from the first wraps to the last, `j` from the last wraps to the first; Enter opens the panel; with the panel open, `j` shows the next task in the panel, keeps focus on the row and adds no history entry; Escape closes and focus returns to the row; `x` completes and the highlight moves to the next row; `e` opens the title editor; `c` focuses quick add; Enter on a focused title button still edits.
